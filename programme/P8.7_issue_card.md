## Waiver-register verdict: DECLARED UNNECESSARY
Declared as data, in `WAIVER_REGISTER`, and carried on every dossier — so "zero waivers" is a recorded assertion rather than an absence a reader has to interpret. The argument is a CLOSED-CASE argument: a certification evidence class can stand in exactly three ways, each already has an honest home, and none is a dispensation. (1) SATISFIED — bound bytes the committed validator accepted; nothing is skipped, so there is nothing to dispense from. (2) PERMANENTLY EXCLUDED — P8.0's register; a statement about host capability, carrying `is_waiver: false` and `revisit_condition: null` by contract. Filing it as a waiver would be exactly the reclassification P8.0 refused: it would turn a permanent, honest, strictly-weaker claim into a temporary dischargeable one somebody could later be told to close. (3) A TYPED ABSENCE — producible, not produced here; it BLOCKS certification, which is the OPPOSITE of a waiver, since a waiver's function is to let a gate pass while a check is missing and nothing in this module can do that. A register would therefore have to invent a fourth case, and the only way to invent one is to reclassify one of the three. The verdict is made unreversible rather than merely stated: 34 dispensation spellings are refused, at any depth, by key, over every object entering the assembly API and over the assembled receipt — so a waiver cannot enter through a plan key, an option, an approval field, or a hand-edited receipt resubmitted for verification. The register's own text is exempt from that scan ONLY by its exact canonical digest, so a register with a waiver added to it fails the scan AND the separate equality check.
