## Difference classification
- Intended correction:
  - **Labels follow the work.** `solver` ← `plan`, owner `stage4_plan_solver`; `case_compilation` ← `semantic_gates`, owner `stage4_semantic_gates`. Every span now also carries a `measures` sentence and an `attribution` block naming the checkpoint ids it claims.
  - **Attribution is a predicate, not a key list.** `validation` claims `verify_*`, `render` and `render_sheet_*`, so a new render leaf is attributed the moment it exists. Any checkpoint id no span claims is reported as `reconciliation.unmapped_checkpoint_ids` and fails validation — the defect class that hid the render leaves cannot recur silently.
  - **Explicit unattributed bucket, declared threshold.** `reconciliation` carries `measured_ms`, `unattributed_ms`, `over_attributed_ms`, `attribution_ratio`, the band, and `threshold_source` (policy path + sha256). Thresholds are READ from `assets/performance-policy-v1.json` — which previously had zero code consumers — via `experience_trace.mjs`, which is now the single threshold authority for the runtime; `performance_receipt.mjs` contains no numeric threshold of its own (the suite pins that). Bands are the policy's own `unknown_gap_warning_ms` / `unknown_gap_investigation_ms` / `unknown_internal_gap_certification_block_ms`; the validator blocks at the certification allowance, which is the policy's `release_policy.block_on_unexplained_internal_gap_over_ms`. The receipt has no span offsets, so it cannot prove a single 300 s gap; it compares the AGGREGATE, which is strictly stronger than the per-gap rule (aggregate >= longest gap) and can never pass something the per-gap rule would block. The ratio target is recorded (`meets_initial_target`) but not blocking, because the policy's 0.95 is a coverage target for the trace, which owns full offsets; asserting it over ten coarse pipeline spans would fail every real run for a reason the receipt cannot localise.
  - **Zero is lawful only as proven reuse.** A checkpoint-backed span whose contributors are ALL in stage 4's declared `reused[]` and whose total is 0 becomes `status: "REUSED"`, `duration_ms: 0`, `lawful_zero_reason: "checkpoint_reuse"`, and counts as covered. Reused vs missing is distinguished by the declared `reused[]`/`executed[]` sets carried into `checkpoint_reuse` in the receipt body — never inferred from the zero itself. An executed checkpoint reporting 0 is still MISSING; a partially reused span keeps the executed time it really measured.
  - **Validator strengthened, never weakened.** Every pre-existing check survives. Added: label↔work (each span's claimed ids must satisfy that span's own predicate — this catches a mislabelled span even after the mutator re-hashes the receipt), no checkpoint claimed by two spans, reconciliation recomputed from the spans rather than trusted as declared, threshold source pinned to the policy digest, and the per-status duration rule that makes a lawful zero provable.
  - **Production caller.** The delivered vNext path now validates the receipt it just compiled and writes `performance-receipt-validation.json` (registered in `artifacts`, so it is hashed into `artifact_sha256`), plus a `summary.performance.receipt` finding carrying status, errors, unattributed ms, band and the reused/missing span names.
- Choice on an invalid receipt — typed finding, not a discarded delivery: an invalid receipt is recorded as `finding_class: PERFORMANCE_RECEIPT_NOT_HONEST` and the run still returns PASS_PENDING_MANUAL. Reasoning: the receipt is a claim ABOUT the run, not a claim the run is correct. Stage 4 has already built, recalculated and independently validated the workbook and its own runtime-budget receipt has already failed closed; destroying a proven deliverable because its stopwatch is unlabelled trades a real product for a bookkeeping defect, and would also give a future author an incentive to weaken the validator to keep deliveries flowing. The finding is loud (own artifact + run summary + typed class) and cannot be confused with a passing receipt. The runtime-budget and progress receipts above it still throw, correctly: those assert the run stayed inside its declared envelope, which IS a claim about the run.
