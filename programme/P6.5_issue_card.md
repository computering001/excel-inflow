## Difference classification

- Intended correction, in four parts.

  **1. The pool is bounded by declared resources.** `assets/lane-resource-policy-v1.json` declares one core and 1536 MiB per lane worker, one core and 1024 MiB held back for the controller, a three-row memory tier table and a hard ceiling of three workers. `resolve_lane_worker_count` takes the minimum of the memory tier, the per-worker memory division, the cpu division and the ceiling — and applies the LANE COUNT LAST, as a bound rather than as the source. This follows stage 4's `validator_concurrency` precedent (size concurrency from a measured resource) instead of inventing a second convention; the difference is that the thresholds are a declaration two runtimes read rather than a ternary in one file. On the developer host (10 cpu / 16 GiB) the two-lane pool still runs two workers, which is exactly what shipped before; on a 2 cpu / 2 GiB box it now runs one.

  **2. Optional work can no longer spend budget mandatory work needs.** The remaining compute is READ from P6.1's persisted ledger via `EXCEL_INFLOW_RUN_DEADLINE` and never written — there is still exactly one clock and one writer, proved by re-reading the ledger bytes after the python has run. Mandatory lanes are capped by the clock but never below `STAGE_FLOOR_MS`; optional lanes see only the surplus above a mandatory reserve of `STAGE_FLOOR_MS × (STAGE_FLOOR_STAGE_COUNT − 2)` = 240 000 ms — the floors of the mandatory stages still downstream of the evidence half. An optional grant below the optional floor is zero: the lane is not started, and its EXISTING containment closes it at zero authority (`broker_timeout` → `contain_optional_broker_failure`), so starvation reuses the containment that was already proven rather than minting a new terminal path. Every declared number in the policy is validated against its source (`STAGE_FLOOR_MS`, `STAGE_FLOOR_STAGE_COUNT`, `DEFAULT_RUNTIME_BUDGETS_MS.broker_global`), so a floor that drifts from P6.1's is a refusal, not two conventions.

  **3. Every executed lane records what it consumed.** `lane-resource-receipt/1.0` names the lane, its priority class and constitutional criticality, its worker slot, the pool's worker count, the cpu/memory it reserved, what it requested, what it was granted, which budget source granted it, the remaining clock at the grant, the wall time and cpu time it consumed, the headroom between grant and consumption, whether it was starved, and whether it closed as a late enrichment. Receipts are written to `lane-resource-receipts.json`, registered as an artifact, and disclosed in `summary.performance.lane_resource_receipts` on every terminal state — a blocked run discloses its consumption exactly as a passing one does. Cpu attribution is honest: a lane that shared the pool declares `pool_shared` and reports `consumed_cpu_ms: null` rather than claiming a measurement the operating system never gave it, and the validator REFUSES a shared receipt that carries a cpu number. Bounding the pool improves measurability — at one worker every lane's reading is exclusive.

  **4. The breaker became a breaker.** It counts failures, compares them with a declared threshold, carries a prior receipt's count forward, takes the remaining budget as an input (minimum = `STAGE_FLOOR_MS`, not a second number), and has three states: a budget-starved breaker OPENS without starting the optional primary at all; a previously open breaker gets exactly ONE trial attempt when budget returns; a successful trial closes it. It returns a `breaker_receipt` and `assertBreakerReceiptCarried` refuses a result that lost it. The four degrade literals are crosswalked to `DEGRADED.broker_evidence_unavailable`, which the registry ALREADY declares. Defaults (`failure_threshold: 1`, `max_attempts: 1`, no budget input) reproduce the previous one-shot behaviour exactly, which is why `broker-exit-fault-injection` is green unchanged at 57 checks.

- Loosening: NONE. Every change either reduces what a run may consume (a worker count that can only fall, a lane watchdog that a grant can shorten and never lengthen) or adds a refusal. The one behavioural addition — an optional lane not started when its grant falls below the floor — routes into containment that already existed and already produced `PASS_DEGRADED` with a zero-authority archive receipt.

- Regression: none attributable. Two suites are red on this tree and both are red IDENTICALLY with all five P6.5 files removed: `ownership-census` ("the committed census no longer matches the source", caused by a concurrent package's edits to `run_user_flow.mjs`/`evidence_work_graph.mjs`/`flow_runtime.mjs`), and the non-attachment half of `prebroker-ownership` (`ModuleNotFoundError: No module named 'fitz'` in the codex-primary-runtime interpreter that `run_user_flow.mjs` is handed — the known local toolchain gap). One genuine regression was found and fixed during delivery: the first implementation added a fifth parameter to `run_lane`, which broke the four-argument test double in `run_prebroker_ownership_controller_tests.py`; the grant now reaches the watchdog through `ACTIVE_LANE_BUDGET_MS` and `effective_lane_timeout_seconds`, `run_lane`'s four-argument boundary is restored, and the suite pins that arity so the same break cannot recur silently.
