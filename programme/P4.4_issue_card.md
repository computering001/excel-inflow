## The six invariants: proven, or unprovable with a reason

- **`unique_node_ids` — PROVEN.** Graph node ids pairwise distinct; module node sets pairwise disjoint; owned ∪ unowned = the graph's node set exactly (38 + 1 = 39). A duplicate cannot hide inside a module.
- **`single_writer` — PROVEN**, over three channels. (a) Each node has exactly one owning module. (b) Each of the 94 declared artifact paths is written by exactly one module. (c) TOTALITY: every field `solveCase` actually emits is claimed by exactly one module or declared solver frame — an unclaimed field is `CENSUS_*_UNCLAIMED`. The one channel that cannot belong to a single module, `forecast[].statement_values` (four modules publish rows into it), is DECLARED shared with its authority named — P4.6's `ECONOMIC_BINDING_ROW_CONTESTED` — and node→row injectivity is re-proven here on every case bound. Claiming it for one module would have been a false single-writer claim.
- **`unit_compatible_edges` — PROVEN PARTIAL, with the remainder declared UNPROVABLE and a specific reason.** Proven: all 71 edges satisfy the declared per-edge-type rule over `tolerance_class`, the only dimensional annotation the graph carries (ten edge types, `control` sources only on `control_gate`, `ratio` sources only on `statement_dependency`); and every one of the 26 module invariants is denomination-homogeneous — no identity mixes native-currency operands with reporting-currency ones, with exactly ONE declared exception, `outputs.undrawn_commitment_is_capacity_less_drawn`, typed `mixed_translation` and required to name both a native operand and the FX rate that carries it across. That exception was found by the validator refusing my own first declaration, not by inspection. Unprovable: true unit compatibility — currency code, unit scale, stock versus flow. Reason, concrete and checked rather than asserted: **no equation-graph node carries a unit**, and `assets/equation-graph.v1.schema.json` declares the node object `additionalProperties: false` over six fixed properties, so one cannot be added without changing a schema asset this package may not touch; and the typed-value contract offers no second source, because `currency` and `unit_scale` exist only on the `reported_number` variant while every solver quantity is `derived_number`, which has neither. The suite probes the graph for a unit annotation and would allow promotion the moment one exists — and REFUSES the promotion while none does.
- **`declared_cross_module_reads_and_writes` — PROVEN.** Every equation edge crossing a module boundary is declared in the consuming module's `read_set` naming the producing module and the exact source node; and every declared `equation_edge` read corresponds to a real cross-module edge. Neither direction can be one-sided.
- **`cycles_only_in_declared_iteration_subgraphs` — PROVEN at node level**, the granularity the solver actually iterates: the single active component has 13 nodes spanning exactly two modules (`cash_rcf`, `interest`), both declare a non-empty `iteration_state`, and the union of the nine declared iteration states equals `solverIterationDeclaration(1).state_vector` EXACTLY. **A quotient-coarsening artifact is declared rather than left to be rediscovered as a violation**: the module quotient graph at circularity=1 carries a THREE-module component `{cash_rcf, debt_instruments, interest}`, because the quotient merges a pure source (`debt.issuance`, `debt.mandatory_repayment`, read by the waterfall) with a pure sink (`debt.pik_accretion`, written from `interest.instrument_pik`) into one vertex. Proven benign, not asserted: no `debt_schedule` node appears in any node-level active component, so `debt_instruments`' empty `iteration_state` is correct — and the suite fails if that ever stops being true.
- **`circularity_off_has_no_active_scc` — PROVEN**, on the graph AND on real solves. `deriveStronglyConnectedComponents(graph, {circularity: 0})` is empty, the module quotient at circularity=0 is acyclic, `solverIterationDeclaration(0)` requires nothing and carries an empty vector, and both certified fixtures re-solved with `controls.circularity = 0` return `active_sccs: []`, `solver_declaration.required: false`, an empty state vector, one iteration and a zero residual. **No vacuous pass is reachable**: handed no circularity-off artifact, the validator ERRORS ("the invariant is not provable against the graph alone") rather than passing, and that is itself a mutation check.

- **Three of the nine modules own NO equation-graph node**: `historical_statements` (the graph's `period_scope` is `single_forecast_period_template` — it has no historical node), `acquisition_overlay` (P4.6's `acquisition` uncovered family; the graph's only acquisition-touching node, `interest.acquisition`, is domain `interest_schedule` and belongs to the interest module under the declared ownership rule) and `outputs_and_ratios` (leverage, liquidity and the definition basis have no node). Their boundaries are still CHECKED — through their artifact write sets, their cross-module reads and their invariants — but their graph half is empty and says so. The suite asserts each of the three has a non-empty artifact boundary, so "no nodes" can never quietly become "no boundary".
- **The nine-module contract cannot own `control.circularity`.** It is a model-level kill switch, not an economic output; P4.6 already types it `solver_control`. It is declared unowned with a reason and a carrier, and the totality obligation requires owned ∪ unowned to be exact — so this is a recorded structural fact, not an omission.
- **Coverage split between corpora, stated rather than discovered.** The FULL boundary binding (carriers, writes, census, mirrors, injectivity) is validated on the two CERTIFIED fixtures, which declare a complete statement structure. The 33-case economics archetype corpus is minimal synthetic — most cases declare only the few statement rows their scenario needs, which P4.6 lawfully types `row_absent` — so it sweeps the 26 module INVARIANTS and the census instead: 31 solvable archetypes, 0 failures; the 2 non-solving archetypes are typed solver refusals (`UNSUPPORTED_INSTRUMENT_CLASS`, `OPENING_DEBT_UNRESOLVED`) and the suite asserts they are typed, so a refusal cannot become a silent skip.
- **What genuinely NEEDS extraction, and why.** The boundaries are validated at the ARTIFACT seam: I can prove that `interest`'s outputs decompose exactly as declared and that `cash_rcf`'s waterfall closes, because those are checkable on the emitted numbers. I CANNOT prove from outside `solveCase` that a module's implementation reads only its declared `read_set` — the whole solve is one lexical scope, so every quantity is in scope for every line, and no boundary crossing is observable. The `read_set` obligation is therefore proven against the GRAPH (every cross-module edge is declared, and every declaration has an edge) and NOT against the code. Closing that requires the Phase-9 extraction, at which point each module becomes a function whose parameter list IS its read set. This package makes that extraction checkable rather than performing it: the contract to extract against now exists, is hash-sealed, and any drift between it and the solver's actual output is caught.
- **The working-capital half of `tax_and_working_capital`** has one artifact output (`change_in_working_capital`) and no equation-graph node, so it is bound and censused but carries no economic invariant of its own. Declared, not repaired.
