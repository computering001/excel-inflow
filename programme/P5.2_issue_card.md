## Difference classification

- Intended correction, in three parts.

  **1. The AST gained a READER.** `parseExpression` is a recursive-descent parser over the same closed vocabulary the renderer enforces: an unknown function, an undeclared operator, a name, a structured reference, whitespace or any character outside the grammar throws `FormulaAstError` rather than being tolerated. It is also EXACT — every parenthesis in the source becomes an explicit `group` node and every numeric lexeme keeps its spelling (`0.000000001` survives, where `String(1e-9)` would have shipped `1e-9`), so `renderExpression(parseExpression(t)) === t` for every text it accepts. `parseExpressionExactly` refuses a tree that does not re-render to its own source, which is what makes the reader usable inside a byte-identity-gated pipeline at all. Proven over all 2980 emitted formulas on the two fixtures: 2980 parse, 2980 round-trip, 0 failures, deepest tree 25 nodes. Sheet-qualified references became structure (`sheetRef`, kind still `ref`, sheet name and address each validated and the name apostrophe-escaped on render) rather than a quoted name spliced in front of an address. Five functions joined `FORMULA_FUNCTIONS` — `AND`, `OR`, `COUNT`, `ISNUMBER`, `DATE` — which with the seven already there is exactly the thirteen the shipped workbook uses; `VLOOKUP` is still refused.

  **2. The gate became a node.** `IF($P$<control>=0,0,<inner>)` is now `conditional(binary("=", [ref, literal(0)]), literal(0), parseExpressionExactly(inner))`, rendered by the one renderer, in one authority (`adjustmentGateAst` / `gateAdjustmentFormula`) read by both the plan rewrite and the sheet-XML pass. Recognition is `adjustmentGateInner`, which reads the gate back off the tree by SHAPE — conditional, `=` test against THIS case's control cell, both zero arms — and returns the inner expression or null. The same function applies the gate and recognises it, so there is no second definition to drift, and the three `startsWith` call sites (plan rewrite idempotence, XML-pass idempotence, `assertShippedPlan`) all now ask the structural question. Wrapping something that is not an expression throws at the cell naming the offset; it can no longer be concatenated and shipped with the gate's own bracket lending it the look of balance. The pro-forma-historical rewrite in column R is likewise a one-node tree rather than an interpolated column letter and row number.

  **3. Twenty-nine of the thirty-one raw literal sites outside `configureOperatingModel` were migrated.** Census before/after, counting code lines only (comment lines mentioning a formula excluded): `configureOperatingModel` 219 → 219 (untouched, by instruction); outside it 31 → 2. Migrated: `sumCellFormula`/`sumCellExpression` (1, now via `sumCellExpressionAst` with a typed term node per compacted run), `applyConditionalState` (7 — conditional-format rules are formulas and are now built like formulas), `brokerEvidenceFormula` (1 — cross-sheet components are `sheetRef` nodes, the multiplier's brackets a declared `group`), `buildBrokersSheet` (10, including the nine-arm case selector, which was assembled by appending `IF(...,` fragments and closing them with `")".repeat(3 + names + provider)` — a bracket count maintained by hand in a second place against a chain built in a first, and is now a right fold over `conditional` nodes with no count to keep), `brokerLink` (1), `signedBrokerLink` (1 — the sign flip is a node above the link, not `"=-ABS(" + link.slice(1) + ")"`, a construction whose correctness rested on the leading `=` being exactly one character wide), `acquisitionRatioRowFormula` (1), `acquisitionAdjustmentFormula` (7 — the four expression fragments its neighbours hand it are now READ into trees by `parseExpressionExactly` and the seven arms COMPOSE nodes; `negatedExpressionAst` states, once, that Excel's unary minus binds tighter than `*` and `/`, which the old `` `=-${amount}` `` relied on silently).

The build's own `plan_assertions.adjustment_gate_cells` is unchanged at 363 (maximal) and 273 (net-cash), which is the interesting number: the structural check and the discarded `startsWith` check agree cell for cell on real data, so the replacement is a pure strengthening rather than a change of population.
