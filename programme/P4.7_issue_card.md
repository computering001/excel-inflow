## Difference classification
- Intended correction: the solve's ORDER and CONVERGENCE become observable and checked without the solve changing. `solve_order.mjs` runs an ITERATIVE Tarjan — written from the algorithm with an explicit frame stack, deliberately not borrowed from `equation_graph.mjs`'s recursive one, so agreement between the two is a cross-check the suite asserts rather than a tautology — condenses the graph into a DAG and produces a deterministic topological order over components and nodes. `solveCase` calls it ONCE per case, at solve time, on the case's own circularity state, and refuses `SOLVE_ORDER_UNDERIVABLE` if the condensation is cyclic. It then re-derives the iteration vector from that decomposition and refuses `SOLVER_ITERATION_VECTOR_NOT_DERIVED` unless the 13-entry literal matches it in membership, multiplicity, tolerance class (read from the graph nodes themselves) and the `required` flag — a second, independent witness beside the contract comparison `compileSolverEquationGraphEvidence` already performs. Inside the period loop a RECORDER captures the order the hand-written solve actually uses: 29 recording sites, each naming its equation-graph node at the point the solve makes that node's value final, plus one call that walks the `statementOverrides` Map's OWN insertion order so the eight-to-eleven statement nodes' relative order is recovered from the code that builds them rather than restated as a list — 39 distinct nodes observable in total. After each period converges, `checkSolveOrderAgreement` proves every dependency edge crossing two components points FORWARD in that observed order, and refuses `SOLVE_ORDER_DISAGREES_WITH_GRAPH` if any does not. Intra-component back edges are reported as the FEEDBACK SET. The residual is decomposed per SCC with the worst node named, an iteration trace records the step residual, the two-cycle residual, the two-cycle verdict and the damping index for every sweep, and `classifyRevolverBinding` turns the two `Math.min` calls into a record carrying both candidate bounds, the winner, the slack and the equation-graph node and edges each bound rides on.

## Reported findings (no solved number changed)
- **HEADLINE — the hand-written order AGREES with the graph-derived order.** Over 33 cases and 99 forecast periods, zero inter-component dependency edges are evaluated backwards. Three distinct observed orders occur (87 / 6 / 6 periods): the 37-node common order, a 39-node order on `standard-maximal-v2` where `cash_interest_paid` and `cash_interest_received` are calculated rather than supplied, and a 31-node order on `revolver_fully_drawn_at_open` which declares no non-revolver instrument. All three agree with the graph. There was no disagreement to report and therefore nothing was reordered.
- **The sweep INTERLEAVES the interest SCC with singleton components in all 99 periods, and this is lawful.** The observed order visits `interest_cash_rcf_feedback` in five blocks separated by `interest.net_expense` and the income-statement chain. Component contiguity is therefore FALSE everywhere. This is why the agreement statement is edge-wise: a rank-monotonic formulation is strictly stronger than topological validity and would have fired on every period of every case in the corpus, reporting a defect where there is none — a Gauss-Seidel sweep is free to compute a downstream node as soon as its own predecessors are known. Contiguity is recorded as an observation (`components_contiguous`, `interleaved_components`) and never as a verdict.
- **The feedback set is exactly three edges, and it is exactly the state the loop carries.** `edge.cash_to_interest_income`, `edge.ending_rcf_to_rcf_interest` and `edge.ending_rcf_to_commitment_fee` are the only intra-SCC edges the observed order traverses backwards; their head set is `{cash.ending_balance, rcf.ending_balance}`, which is precisely the trio of variables (`endingCash`, `endingRcf`, `endingRcfNative`) the iteration carries across sweeps and precisely the trio the two-cycle damping branch damps. The derivation and the hand-written code agree on WHICH lag makes the loop a loop, which nothing previously stated. Removing those three edges leaves the SCC acyclic under the observed order — asserted, not assumed.
- **The 13-entry literal is exactly the derived SCC, and its ORDER carries no meaning.** The literal's node set equals the single 13-node cyclic component derived from the graph. Its listed order, however, is not the sweep order — the literal starts at `statement.cash_flow_start` while the sweep starts at `interest.rcf` — and that is harmless only because the residual is an L-infinity norm, which is order-invariant. Recorded here so a future reader does not mistake the literal for a schedule.
- **The binding-constraint distribution over the corpus** (99 periods, `side/draw/repayment`): `neither/tie/opening_balance` 68, `neither/undrawn_capacity/tie` 16, `neither/cash_need/opening_balance` 6, `repayment/cash_need/cash_surplus` 3, `neither/undrawn_capacity/cash_surplus` 3, `draw/cash_need/suppressed_by_draw` 2, `repayment/cash_need/opening_balance` 1. Every active draw in the corpus is bound by CASH NEED, never by capacity; no period in the corpus exhausts revolver headroom while drawing. The `tie` verdicts are the economically empty periods — no deficit and no headroom, or no surplus and no opening balance — which the previous `Math.min` reported identically to a real bind.
- **No case in the corpus ever needed the damping branch.** `two_cycle_detected` is false in every sweep of every period; the maximum iteration count is 8 and the maximum per-SCC residual at convergence is 8.17e-9 against a declared tolerance of 1e-8. The suite PINS the absence, so if a corpus case ever begins to oscillate it fails loudly instead of quietly damping.
